# Metadata Verification

**Date:** 2026-09-11
**Scope:** the public routes that exist today — `/`, `/blog`, `/blog/[slug]`
**API:** Next.js App Router metadata (`metadata`, `generateMetadata`,
`opengraph-image` convention)
**Verified against:** a production build served locally, not `next dev` —
metadata resolution and image generation differ.

Service-specific metadata is deliberately absent: those routes do not exist
yet and belong to Phase 2.

## 2. Open Graph image

Generated by `next/og` at `src/app/opengraph-image.tsx`. No binary committed —
the card cannot drift from the copy, and there is no asset to re-export when
wording changes.

**Design.** White ground with a blue gradient rule across the top matching the
site's `#016ecc → #19d2fe`; the F mark in a gradient tile beside the
Forgeline / TECHNOLOGIES lockup; the site's own claim, *"We build the site that
wins you the work."*; and a capability rail reading
Web apps · Websites · E-commerce · **Fixed scope, fixed price**.

**No `next/font` call.** A Google Fonts fetch inside the image route would make
every build depend on network access. System faces only.

**Verified output**

```
GET /opengraph-image        → 200  image/png  39,903 bytes  1200 × 630 ✓
GET /blog/opengraph-image   → 200  image/png  39,903 bytes  1200 × 630 ✓
```

Measured by reading the PNG IHDR header, not by trusting the declared
`og:image:width` meta tag.

## 4. Two inheritance bugs found during verification

Both were introduced by this task and caught before finishing. Recording them
because they are easy to reintroduce.

### 4.1 A canonical in the layout makes every page a duplicate

The first implementation put `alternates: { canonical: "/" }` in the root
layout. Metadata is inherited, so `/blog` would have declared itself canonical
to `/` — telling search engines the blog is a duplicate of the homepage.

**Fix:** canonical is set per page. The layout carries none, with a comment
saying why.

### 4.2 `openGraph` is replaced, not merged

Setting `openGraph: { url: "/" }` on the homepage silently dropped `og:type`,
`og:site_name`, `og:locale`, `og:title` and `og:description` inherited from
the layout. Next merges metadata **shallowly** — a page that sets `openGraph`
replaces the parent's whole object.

Verification showed `og:type` and `og:site_name` missing and `og:description`
falling back to the plain description.

**Fix:** `src/lib/metadata.ts` exports `openGraph()`, which returns a complete
object. Every page that needs a page-specific `og:url` calls it, so no page
can emit a partial object.

### 4.3 The image convention does not cascade

`opengraph-image.tsx` applies to the segment it sits in and **not** to nested
segments. With only the root file, `/blog` and `/blog/[slug]` shipped no
`og:image` at all — verified as missing before the fix.

**Fix:** `src/app/blog/opengraph-image.tsx` and
`src/app/blog/[slug]/opengraph-image.tsx` re-export the root implementation:

```ts
export { default, size, contentType, alt } from "../opengraph-image";
```

Re-exported rather than duplicated, so there is exactly one card design.

## 6. Notes and caveats

### Canonical host is unverified against production

Everything uses the apex domain `https://forgelinetechnologies.com`, matching
`sitemap.ts`, `robots.ts` and `metadataBase`. `lib/content.ts` still carries a
`www` variant, but nothing imports it.

**This could not be confirmed against the live site.** At the time of writing
both hostnames return `404 DEPLOYMENT_NOT_FOUND` from Vercel — the domain is
attached to a project with no deployment behind it.

Once the site is serving again, confirm which host Vercel treats as primary.
If it is `www`, three files must change together — `layout.tsx`,
`sitemap.ts`, `robots.ts` — or they will contradict each other.

### The blog is delinked but indexable

Task 7 removed `/blog` from the navigation and the sitemap while it has fewer
than three posts. It is still crawlable if discovered, and now carries correct
canonical and OG data, which is the right posture: not promoted, not broken.

### Not done, by instruction

No service-specific metadata. `/services`, `/work`, `/pricing`, `/contact` do
not exist yet; their metadata belongs with the routes in Phase 2.
