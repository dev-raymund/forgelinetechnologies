# Forgeline Implementation Plan

Derived from `WEBSITE-AUDIT.md`. Sequenced for one outcome: turning the site
into something that acquires clients.

**Status:** planning only. No code changed to produce this document.

---

## Current architecture

Verified against the running app, the component source, and the live Neon
database — not from memory.

### Framework and routing

Next.js 15 App Router, React 19, TypeScript strict mode, path alias `@/*` → `src/*`.
Routing is file-based; there is no custom router or route config.

| Route | File | Rendering |
|---|---|---|
| `/` | `src/app/page.tsx` | ISR, `revalidate = 3600` |
| `/blog` | `src/app/blog/page.tsx` | ISR, `revalidate = 3600` |
| `/blog/[slug]` | `src/app/blog/[slug]/page.tsx` | SSG via `generateStaticParams` |
| `/admin/login` | `src/app/admin/login/page.tsx` | Dynamic |
| `/admin/*` | `src/app/admin/(dash)/**` | Dynamic — works, posts, users CRUD |
| `/econtent/*` | `src/app/econtent/**` | Unrelated placeholder build, `noindex` |
| `/robots.txt` | `src/app/robots.ts` | Static |
| `/sitemap.xml` | `src/app/sitemap.ts` | Static |

**Two public URLs exist.** Everything the navigation offers (Products, Process,
Work, About, FAQ) is an in-page anchor on `/`.

### Homepage composition

`src/app/page.tsx` fetches works and posts, then renders five components:

```
StaticTop      366 lines   nav, hero, services, packages, process, counters
WorkSection     85 lines   the 17-project grid (takes works as props)
BlogTeaser      49 lines   3 latest posts (takes posts as props)
StaticBottom   168 lines   testimonials (hidden), founder, FAQ, lead form, footer
SiteScripts    116 lines   nav behaviour, reveal animations, counter animation
```

> **Architectural hazard.** `static-top.tsx` and `static-bottom.tsx` both carry
> a header comment: *"AUTO-GENERATED by scripts/port-homepage.mjs from
> site/index.html. Re-running the script overwrites this file."*
> `scripts/port-homepage.mjs` still exists, and these files have since been
> edited by hand (the lead form was rewired). Running that script now destroys
> that work. See **P0-3**.

### Database

Neon Postgres via Drizzle (`@neondatabase/serverless`, `drizzle-orm/neon-http`).
Schema in `src/db/schema.ts`, queries in `src/lib/queries.ts`.

| Table | In schema | In live DB | Purpose |
|---|---|---|---|
| `users` | yes | **yes** | Admin accounts, scrypt hashes, admin/editor roles |
| `works` | yes | **yes** | 17 projects — title, slug, category, badge, description, imageUrl, liveUrl, sortOrder, published |
| `posts` | yes | **yes** | Blog — currently 0 rows |
| `project_inquiries` | yes | **NO** | Contact submissions — defined but never pushed |

`works` already has a `slug` column with a unique constraint. The data needed
for case-study URLs exists; the route does not.

`src/lib/queries.ts` wraps every read in `withRetry()`, which retries
connection-level failures (Neon cold starts) with 300ms/600ms backoff and
rethrows genuine SQL errors immediately.

### Contact pipeline

```
components/forms/lead-form.tsx   client component, useActionState + useFormStatus
        ↓
app/actions/inquiry.ts           server action
        ↓  Zod parse (lib/validation/inquiry.ts)
        ↓  honeypot check (_gotcha) — silent success, no write
        ↓  IP rate limit, 5/hour, counted in the database
        ↓  INSERT into project_inquiries        ← TABLE DOES NOT EXIST
        ↓  Resend notification + confirmation   ← NO API KEY SET
```

Storage happens before email deliberately, so a Resend outage costs the
notification rather than the lead. Both halves are currently non-functional.

### Stats rendering

`src/components/static-top.tsx:353–358` — the literal text content is `0`:

```html
<strong data-to="6" data-suffix="+">0</strong><span>Years building</span>
<strong data-to="17">0</strong><span>Projects shipped</span>
<strong data-to="4">0</strong><span>Countries served</span>
<strong data-to="100" data-suffix="%">0</strong><span>Code ownership</span>
```

`src/components/site-scripts.tsx:29–55` finds `.counter strong[data-to]` and
animates via `IntersectionObserver`. Without JavaScript, or before the observer
fires, the served HTML reads zero.

### SEO implementation

- `src/app/layout.tsx` — `metadataBase`, title template, description, favicon.
- `src/app/sitemap.ts` — homepage, `/blog`, and published posts; falls back to
  static routes if the database is unreachable.
- `src/app/robots.ts` — allows all, disallows `/admin` and `/econtent`; returns
  a blanket `Disallow: /` when `isStaging`.
- `generateMetadata` exists on exactly one route: `blog/[slug]`.
- **Absent:** Open Graph, Twitter card, canonical, JSON-LD.

### Image handling

35 raw `<img>` tags, zero `next/image`:

| File | Count |
|---|---|
| `static-top.tsx` | 32 (mostly inline decorative SVG) |
| `work-section.tsx` | 2 (project thumbnails) |
| `static-bottom.tsx` | 1 (founder portrait) |

On disk: 2.8 MB of project JPEGs (largest 248 KB) and a 208 KB founder PNG.
`next.config.ts` permits any HTTPS remote pattern; the optimiser is available
and unused.

### Blog implementation

`marked` renders post bodies (`src/lib/markdown.ts`) into `dangerouslySetInnerHTML`.
This is a renderer, not a sanitiser — safe only while authoring is restricted to
signed-in admins, which it currently is. `generateStaticParams` catches database
failure and falls back to on-demand rendering rather than failing the build.

### Repository state

`web/` is **untracked in git**. Everything above — the whole application — has
no version history. Listed as **P0-0** because it gates safe execution of the
rest of this plan.

## P0 — Must complete before outreach

Outreach means sending links to strangers. Each item here is something that
breaks, embarrasses, or silently loses a lead at that moment.

### P0-0 — Commit the application to git

**Problem.** `web/` is untracked. There is no history, no diff, no revert. Every
task below modifies it. A mistake mid-plan is unrecoverable.

**Solution.** Verify `.gitignore` excludes `.env`, `node_modules/`, `.next/`,
`drizzle/`. Commit `web/`, `CLAUDE.md`, `WEBSITE-AUDIT.md` and this plan.
Decide whether `web/_archive-redesign/` is committed or deleted first.

**Files.** `web/**`, `.gitignore`, `CLAUDE.md`, `docs/`, `WEBSITE-AUDIT.md`

**Dependencies.** None. Do this first.

**Acceptance.** `git status` clean; `git log` shows the commit; `git show --stat`
confirms no `.env` or `node_modules` included.

---

### P0-1 — Create the `project_inquiries` table

**Problem.** The table is defined in `schema.ts` but does not exist in Neon
(live tables: `posts`, `users`, `works`). The contact form's `INSERT` throws,
the action returns its error branch, and the visitor is told to email instead.
Every enquiry driven by outreach is lost.

**Solution.** Run `npm run db:push`. The change is purely additive — one new
table plus two indexes. No existing table is touched. Verify against
`information_schema` afterwards rather than trusting the command's output.

**Files.** `web/src/db/schema.ts` (already correct), live Neon database

**Dependencies.** P0-0.

**Acceptance.** `project_inquiries` appears in `information_schema.tables`; a
test submission through the live form inserts a row with the correct
`projectType`, `budget` and `sourceIp`; the form shows its success state.

---

### P0-2 — Configure Resend

**Problem.** `RESEND_API_KEY`, `CONTACT_EMAIL` and `RESEND_FROM` are unset. The
email module returns `{ ok: false, skipped: true }`. Enquiries would land in the
database with nobody notified — arguably worse than an error, because the
failure is silent.

**Solution.** Create a free Resend account (3,000/month, 100/day). Verify the
sending domain, or accept the shared `onboarding@resend.dev` sender, which only
delivers to the account's own address and is therefore fine for testing but not
for client confirmations. Set all three variables locally and in the host.

**Files.** `web/.env`, host environment variables, `web/.env.example` (documented)

**Dependencies.** P0-1 — test the whole path at once.

**Acceptance.** A test submission produces a row in `project_inquiries`, a
notification to `CONTACT_EMAIL` with `Reply-To` set to the enquirer, and a
confirmation to the enquirer. Server logs show no `[inquiry]` errors.

### P0-3 — Retire the homepage port script

**Problem.** `static-top.tsx` and `static-bottom.tsx` declare themselves
auto-generated from `site/index.html`, and `scripts/port-homepage.mjs` still
exists. Those files have since been edited directly — the Formspree form was
replaced with the wired `<LeadForm />`. Running the script silently reverts that
and restores a form posting to a third-party endpoint.

**Solution.** Delete `scripts/port-homepage.mjs` and `scripts/html-to-jsx.mjs`,
remove the auto-generated header comments, and decide the fate of the legacy
`site/` directory at the repo root. Every P0/P1 task below edits these two files;
this must happen before them.

**Files.** `web/scripts/port-homepage.mjs`, `web/scripts/html-to-jsx.mjs`,
`web/src/components/static-top.tsx`, `web/src/components/static-bottom.tsx`,
`site/` (root)

**Dependencies.** P0-0.

**Acceptance.** Port scripts gone; header comments removed; `grep -r formspree web/src`
returns nothing; homepage renders unchanged.

---

### P0-4 — Server-render the statistics

**Problem.** The credibility band ships `0` in the HTML. First paint, no-JS
visitors, and every scraper and link-preview bot see a studio with no track
record. The one section built to prove experience currently disproves it.

**Solution.** Render the real value as the element's text content and let the
animation count *from* that number, or skip animating when it is already
correct. Keep `data-to` as the animation target. The figures — 6+, 17, 4, 100% —
are already known and defensible.

**Files.** `web/src/components/static-top.tsx` (353–358),
`web/src/components/site-scripts.tsx` (29–55)

**Dependencies.** P0-3.

**Acceptance.** `curl localhost:3001/ | grep -o '<strong data-to[^<]*<'` shows
real numbers, not `0`. With JavaScript disabled the band reads correctly. The
animation still runs for JS visitors without flashing zero.

---

### P0-5 — Resolve the empty blog

**Problem.** `/blog` is in the main navigation and the sitemap, returns 200, and
renders "No posts published yet." A nav link to an empty page reads as an
abandoned business — worse than no link.

**Solution.** Pick one. **(a)** Publish three posts before outreach begins, or
**(b)** remove the nav link, drop `/blog` from the sitemap, and leave the route
live but unlinked until there is content. (b) is the honest default if posts are
not imminent.

**Files.** `web/src/components/static-top.tsx` (nav), `web/src/app/sitemap.ts`,
optionally `posts` rows via `/admin`

**Dependencies.** P0-3.

**Acceptance.** Either `/blog` lists ≥3 posts, or the nav contains no blog link
and `/sitemap.xml` contains no `/blog` entry. No route returns an empty state to
a visitor who followed a link.

---

### P0-6 — Open Graph, Twitter and canonical metadata

**Problem.** Zero occurrences of `og:*`, `twitter:card`, and `canonical`. Every
link pasted into LinkedIn, Slack, WhatsApp or an email renders as a bare grey
rectangle. For a business whose acquisition channel is outreach, the link
preview is the first impression — and it is currently blank.

**Solution.** Add `openGraph`, `twitter` and `alternates.canonical` to the root
metadata, and per-route overrides as routes are added. Generate an OG image via
`opengraph-image.tsx` using `next/og` so there is no binary asset to keep in
sync with the copy.

**Files.** `web/src/app/layout.tsx`, new `web/src/app/opengraph-image.tsx`,
per-route `metadata` exports

**Dependencies.** None strictly, but re-verify after P1-1 adds routes.

**Acceptance.** Homepage HTML contains `og:title`, `og:description`, `og:image`,
`twitter:card` and a canonical link. The OG image renders at 1200×630. A pasted
link previews correctly in at least one real client.

---

### P0-7 — Obtain and publish real testimonials

**Problem.** No third party vouches for the work anywhere on the site. The
testimonials section is correctly hidden rather than filled with placeholders,
but the effect is that a stranger arriving from outreach has only the studio's
own word. This is the single widest gap in the funnel.

**Solution.** Ask three past clients in writing for two or three sentences and
explicit permission to publish name, role and company. Prioritise the ones with
the strongest outcome and the fastest reply. Un-hide the section and populate
it. If only one arrives, publish one — one real named quote outperforms three
anonymous ones.

**Files.** `web/src/components/static-bottom.tsx` (remove `hidden={true}`,
replace placeholder content)

**Dependencies.** P0-3. Blocked on client replies — start this first, it has the
longest lead time of anything in P0.

**Acceptance.** At least one attributed testimonial with name and company is
live, with written permission on file. No placeholder text remains in the
section. If none are obtained, the section stays hidden — it is never populated
with invented content.

## P1 — Important for conversion and SEO

### P1-1 — Split the site into real routes

**Problem.** Two URLs. Nothing ranks separately, nothing can be linked in an
email, nothing can be attributed. Six service lines and four target markets
compete for one page.

**Solution.** Add `/services`, `/services/[slug]`, `/work`, `/work/[slug]`,
`/pricing` and `/contact`. Extract shared chrome (header, footer) into
components used by every route. Keep `/` as the overview that links onward
rather than duplicating those pages.

**Files.** New `web/src/app/{services,work,pricing,contact}/**`, extracted
`web/src/components/site-header.tsx` and `site-footer.tsx`,
`web/src/components/static-top.tsx`, `web/src/components/static-bottom.tsx`,
`web/src/app/sitemap.ts`

**Dependencies.** P0-3, P0-0.

**Acceptance.** Each route returns 200 with a unique `<title>`, description and
canonical. Sitemap lists all of them. Header and footer are single components,
not duplicated markup. Homepage still renders identically.

---

### P1-2 — Case-study pages

**Problem.** 17 projects, zero detail pages, ~110 characters of description
each. Evidence without argument — nothing explains what was solved or why it
justifies a $4,000 build.

**Solution.** Add `/work/[slug]` using the existing unique `slug` column, with
`generateStaticParams` and per-project `generateMetadata`. Write three real case
studies first: problem, constraint, what was built, what shipped. Extend the
`works` schema with optional long-form fields, or add a `case_studies` table —
optional, so the other 14 projects render as they do now.

**Files.** New `web/src/app/work/[slug]/page.tsx`, `web/src/db/schema.ts`,
`web/src/lib/queries.ts` (`getWorkBySlug` already exists in history),
`web/src/components/work-section.tsx` (link the cards)

**Dependencies.** P1-1. Schema change requires a `db:push` — same care as P0-1.

**Acceptance.** Three projects have full case studies at their own URLs; the
remaining 14 render a valid short page or are excluded from linking. All appear
in the sitemap. No invented metrics or outcomes anywhere.

---

### P1-3 — Optimise images

**Problem.** 2.8 MB of raw JPEGs plus a 208 KB PNG, served through plain `<img>`
with no responsive sizing or modern format. Mobile visitors in the target
markets download desktop-resolution screenshots.

**Solution.** Convert the three content images (2 project thumbnails, 1 founder
portrait) to `next/image` with correct `sizes` and lazy loading below the fold.
Leave the 32 inline decorative SVGs alone — they are not raster images and
`next/image` does not apply.

**Files.** `web/src/components/work-section.tsx`,
`web/src/components/static-bottom.tsx`

**Dependencies.** P0-3.

**Acceptance.** Homepage HTML contains `/_next/image` URLs for project and
founder images. Transferred image bytes on a cold mobile load drop
substantially. No layout shift introduced — verify explicit dimensions.

---

### P1-4 — Structured data

**Problem.** Zero JSON-LD. No eligibility for organisation, service or FAQ rich
results — free SERP real estate for a site with little else competing.

**Solution.** Emit `Organization`, `Service` (per service page) and `FAQPage`
JSON-LD, sourced from the same data the pages render so the markup cannot drift
from the visible content, which is what gets penalised.

**Files.** New `web/src/components/structured-data.tsx`,
`web/src/app/layout.tsx`, service and FAQ routes

**Dependencies.** P1-1 (service pages must exist first).

**Acceptance.** Google Rich Results Test passes for Organization and FAQPage.
Every JSON-LD value appears verbatim in the rendered page.

---

### P1-5 — Accessibility landmarks

**Problem.** No `<main>` element and no skip link. Keyboard and screen-reader
users traverse the whole navigation on every page with nothing to skip to.

**Solution.** Wrap page content in `<main id="main">` and add a visually-hidden
skip link as the first focusable element. Everything else is already sound —
`lang` set, 0 of 50 images missing alt, every form control labelled.

**Files.** `web/src/app/layout.tsx` or the extracted shell from P1-1,
`web/src/app/site.css`

**Dependencies.** Best done during P1-1.

**Acceptance.** Exactly one `<main>` per page. Tab from page load reveals a
visible skip link that moves focus to `#main`. axe reports no landmark or
bypass-block violations.

---

### P1-6 — Standardise calls to action

**Problem.** Eight CTA buttons carry four labels — "Get started" ×4, "Start a
project" ×2, "See our work", "Book a scoping call". Three mean the same thing
and land in the same place, which costs recognition and makes conversion
impossible to attribute.

**Solution.** One primary label — "Start a project" — and one secondary, "See
our work". Keep "Book a scoping call" only where it genuinely offers the
lower-commitment path, near the form.

**Files.** `web/src/components/static-top.tsx`,
`web/src/components/static-bottom.tsx`, any new route from P1-1

**Dependencies.** P0-3.

**Acceptance.** At most two distinct primary CTA labels site-wide. Every
instance links to the same destination for the same label.

---

### P1-7 — Multiple conversion paths

**Problem.** One form, below ~1,300 words, as the only exit. No header CTA, no
phone, no calendar, no email presented as an action. Buyers who are ready now
must read the process section first.

**Solution.** Add a persistent header CTA, an email address in the footer, and a
calendar link for the free scoping call. Keep the form as the considered path,
not the only one. Move the response-time promise adjacent to the submit button,
which is where hesitation actually occurs (audit L3).

**Files.** `web/src/components/static-top.tsx` (header),
`web/src/components/static-bottom.tsx` (footer, form),
`web/src/components/forms/lead-form.tsx`

**Dependencies.** P0-1, P0-2 — do not drive more traffic at a form that cannot save.

**Acceptance.** A visitor can convert from the header without scrolling. Footer
exposes a mailto. Calendar link resolves. Response-time promise visible within
one viewport of the submit button.

## Constraints carried from CLAUDE.md

These are project rules, not preferences. They apply to every item above.

- Never fabricate client results, testimonials, or technologies used.
- Never claim an improvement that cannot be verified.
- Prefer business outcomes to technical jargon in client-facing copy.
- Position Forgeline as a studio, not a freelancer-marketplace profile.

The case studies in P1-2 and the testimonials in P0-7 are where these rules bite
hardest. If a project's outcome cannot be substantiated, the case study
describes the constraint and the decision instead — which is more persuasive to
a technical buyer than an unverifiable percentage.
